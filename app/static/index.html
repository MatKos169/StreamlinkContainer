Einstellungen
Wie oft alle Kanäle bei Twitch geprüft werden. Für Kanäle ohne eigene Qualität, z.B. 1080p60,720p60,best. Nach dem Ende eines Streams wird der Kanal so oft direkt geprüft, damit ein Neustart nach einer Unterbrechung schnell erkannt wird. Wie lange nach Stream-Ende schneller geprüft wird. 0 schaltet die Nachprüfung ab. Ordner unterhalb des Ausgabeordners, z.B. für eine übersichtliche Jellyfin-Bibliothek. Gilt für neue Aufnahmen. Die aufgenommene .ts-Datei nach der Umwandlung im Arbeitsordner (done/) aufheben statt löschen. Aufgehobene .ts-Dateien in done/ werden nach so vielen Tagen automatisch gelöscht (einmal pro Stunde, vom Recorder). 0 = nie. loudnorm auf -14 LUFS, Audio als AAC 192k. Aus: Audio wird unverändert übernommen. copy übernimmt das Video unverändert (schnell, verlustfrei). Ein Codec wie libx264, libx265 oder libsvtav1 kodiert neu – deutlich langsamer, Qualität/Größe über eigene Parameter steuern (z.B. -crf 23 -preset medium). Standard für VOD-Downloads. Echtzeit schont Bandbreite und Twitch, dauert aber so lange wie das VOD (÷ Tempo). 1 = Wiedergabegeschwindigkeit, 2 = doppelt so schnell. Parallele Segment-Downloads im Download-Modus (streamlink stream-segment-threads). Weitere VODs warten, bis einer fertig ist. Live-Aufnahmen und VOD-Downloads zusammen. Ist das Limit erreicht, startet kein neuer VOD-Download; Live-Aufnahmen laufen immer. Nach einem Stream-Ende bleibt der Platz für die eingestellte Reservierungszeit belegt. 0 = kein Limit. So lange hält ein Kanal nach dem Ende seines Streams seinen Platz im Limit, falls der Stream wiederkommt. In der Kanalliste per „Platz freigeben“ vorzeitig lösbar. 0 = sofort frei. Werden direkt vor der Ausgabedatei angehängt und überschreiben damit die Optionen oben (z.B. -c:a copy, -vf scale=-2:720). Nicht erlaubt: -i, -progress, -y, -n. Gilt für neue Aufnahmen und für „Erneut versuchen“.
